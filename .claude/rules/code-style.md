# Code Style

No `.clang-format`, `.editorconfig`, or `.prettierrc` exists yet. Until one is added, match the
style already present in the file you're editing rather than introducing a new convention.

## C++ (`src/*.cpp`, `src/*.h`)

- C++17, 2-space indent, no tabs
- Sciter windows subclass `sciter::window` and declare their script-visible surface with the SOM
  passport macros:

  ```cpp
  class MainWindow : public sciter::window {
  public:
    MainWindow() : window(SW_MAIN | SW_ENABLE_DEBUG) {}

    SOM_PASSPORT_BEGIN(MainWindow)
    SOM_PASSPORT_END
  };
  ```

- Keep `uimain()` focused on window setup and resource loading — push feature logic into the
  window class or a dedicated helper function (see `dev_main_htm_url` in `src/main.cpp`).
- `src/resources.cpp` is generated by `packfolder.exe` at pre-build — never hand-edit it.

## JavaScript / CSS (`res/**`)

- ES modules with JSDoc typedefs for types — `checkJs: true` in `jsconfig.json` type-checks this
  against `sciter.d.ts` / `sciter-extra.d.ts`, so keep JSDoc annotations accurate (see
  `res/shared/lib/router.js` for the pattern: `@typedef`, `@param`, `@returns` on every export).
- 2-space indent, `export function` for public API (avoid default exports)
- Design tokens (colors, spacing, radius) belong in `res/shared/lib/tokens.css` as CSS variables —
  don't hardcode raw values in component styles once components exist.

## Naming

- C++ classes: `PascalCase` (`MainWindow`)
- JS functions/variables: `camelCase`; JS types (via `@typedef`): `PascalCase`
- Files: `kebab-case` for JS/CSS (`tokens.css`, `router.js`), matching existing `res/` layout
